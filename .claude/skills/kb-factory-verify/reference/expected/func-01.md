**Query:** How do I create a product with variants and configure its visibility per sales channel, and why might it not show up in the storefront?

**Expected answer — every fact an answer must contain:**

1. Before the first save the product mask requires Title (only in the system default language), Product number, Tax rate, Price (net **and** gross, per currency) and Stock — these are the DAL `Required` fields of `product`/`product_translation` surfaced through the entity schema. On the create route **no** tab bar is rendered at all (`<sw-tabs v-if="productId">`, and the create route passes no `productId`), so every tab — General, Specifications, Advanced prices, Variants, Layout, SEO, Cross-selling, Reviews — appears only after the first save redirects to the detail route. `[code: Content/Product/ProductDefinition.php:161,172,173,180 + Content/Product/Aggregate/ProductTranslation/ProductTranslationDefinition.php:59; administration bundle: src/module/sw-product/page/sw-product-detail/sw-product-detail.html.twig:148, src/module/sw-product/page/sw-product-detail/index.js:1074-1083, src/app/service/entity-validation.service.ts:109-141]`
2. Per-sales-channel visibility is **not** a field on the product: it is a separate `product_visibility` row per channel, whose `productId`, `salesChannelId` and `visibility` are all `Required`, and whose level is one of exactly three values enforced by a strict `Choice` — `10 VISIBILITY_LINK` (hide in listings and search, reachable by URL), `20 VISIBILITY_SEARCH` (hide in listings), `30 VISIBILITY_ALL` (visible). Storefront reads gate on `ProductAvailableFilter`, which ANDs `visibilities.visibility >= threshold`, `visibilities.salesChannelId = <current channel>` and `product.active = true`, with the threshold set per route (listing 30, search/suggest 20, detail 10; any SalesChannelProduct read without such a filter gets one at level 10 injected). So a product is invisible when it has no visibility row for that channel, when its level is below the route's threshold, or when `active` is false — and additionally absent from a category listing when it is not in `product.categoriesRo` for that category, and from listings when `core.listing.hideCloseoutProductsWhenOutOfStock` is on and it is a closeout product with `available = false`. `visibilities`, `active` and `isCloseout` are `Inherited`, so variants inherit the parent's channel visibility unless they define their own. This is identical in 6.6 and 6.7. `[code: Content/Product/Aggregate/ProductVisibility/ProductVisibilityDefinition.php:24-28,63-68; Content/Product/SalesChannel/ProductAvailableFilter.php:17-29; Content/Product/SalesChannel/SalesChannelProductDefinition.php:44-50; Content/Product/SalesChannel/Listing/ProductListingRoute.php:68,108-126; Content/Product/SalesChannel/ProductCloseoutFilter.php:16-21; Content/Product/ProductDefinition.php:176-180,259]`
3. A variant is a `product` row with `parentId` plus `options` (many-to-many to `property_group_option`); the parent declares the offered options through `configuratorSettings`. Which row a listing shows is decided by the **write-protected** `display_group` column, computed by `VariantListingUpdater` from `variant_listing_config` — the listing loader groups on `displayGroup` and filters `NotEquals(displayGroup, null)`, so a parent with children is hidden (`display_group = NULL`) and, when the config carries no groups, every child is stamped with the same `SHA2(HEX(parent_id))` so the listing collapses to **one arbitrary child variant**. In 6.7 (verified 6.7.13.0) "Generate variants" never persists `variantListingConfig`: the generator sets `displayParent: true` only in memory and the modal syncs children, variant restrictions and configurator settings, then reloads the product — so the column stays NULL, `ProductListingLoader::loadPreviews()` `continue`s past the NULL row and performs no child→parent remapping, and no 6.7 migration backfills a NULL config. The admin's Storefront-presentation form resolves a NULL config to `Expand property values in product listings`, not to `Display single product` (whose sub-options are `Main product` and `Variant`). `[code: Content/Product/ProductDefinition.php:183-184,257,273; Content/Product/Aggregate/ProductConfiguratorSetting/ProductConfiguratorSettingDefinition.php:61-66; Content/Product/DataAbstractionLayer/VariantListingUpdater.php:52-83; Content/Product/SalesChannel/Listing/ProductListingLoader.php:211-215,228-266; Migration/V6_7/ (no variant_listing_config migration); administration bundle: src/module/sw-product/helper/sw-products-variants-generator.js:154-168, src/module/sw-product/component/sw-product-variants/sw-product-modal-variant-generation/index.js:336-355, src/module/sw-product/component/sw-product-variants/sw-product-modal-delivery/index.js:51-57, src/module/sw-product/snippet/en.json:436-442]`
