**Query:** How do I create an integration for Admin API access in the administration and give it the right privileges?

**Expected answer — every fact an answer must contain:**

1. Integrations are created in the administration under **Settings > System > Integrations** — the `sw-integration` module, a settings item in the `system` group at route `sw.integration.index`, gated by the `integration.viewer` privilege; creating one additionally needs `integration.creator` (`integration:create`), editing needs `integration.editor` (`integration:update`, `api_action_access-key_integration`, `integration_role:create/delete`). Same privilege mapping on 6.6 and 6.7. `[code: administration src/module/sw-integration/index.js:14-46; administration src/module/sw-integration/acl/index.js:16-56]`
2. Privileges are given to an integration in exactly one of two ways, and nowhere else: assign **ACL roles** (the `aclRoles` many-to-many from `integration` to `acl_role` via `integration_role`) or set the boolean **admin** flag, which makes the request source an admin source that skips ACL write validation. There is no privileges field on the integration entity, and in the UI the role select is disabled while the integration is marked administrator. The `admin` field is `WriteProtected(Context::SYSTEM_SCOPE)`, so it cannot be set by a generic entity write — it is written only by `IntegrationController` (`POST /api/integration`, `PATCH /api/integration/{id}`), which the administration calls as a separate `updateAdmin` request after saving. This split exists on both 6.6 and 6.7. `[code: System/Integration/IntegrationDefinition.php:63-79; Framework/Api/Controller/IntegrationController.php:34-63; Framework/Api/Acl/AclWriteValidator.php:52]`
3. Saving issues an **access key** and a **secret access key**, generated by `GET /api/_action/access-key/intergration` (upstream spelling; privilege `api_action_access-key_integration`). The generator persists nothing and `secretAccessKey` is a `PasswordField`, so the secret exists only at creation time and must be copied then; regenerating issues a new access key **and** a new secret. The pair is used as `client_id` / `client_secret` in the OAuth `client_credentials` grant at `POST /api/oauth/token`. `[code: Framework/Api/Controller/AccessKeyController.php:18-29; System/Integration/IntegrationDefinition.php:66; Framework/Api/Controller/AuthController.php:33]`

**Official reference URL:** https://docs.shopware.com/en/shopware-6-en/settings/system/integrationen
