## What it is
Documents the ACL Routing component, which blocks Controller Actions for B2B users by mapping an `action` in a given `controller` to a `resource` (entity type) and `privilege` (class of actions), extending the base ACL component.

## Key steps / config
Routes needing access rights are declared in an array and synced to the database. The array shape:

```php
$myAclConfig = [
    'contingentgroup' => [        // resource name
        'B2bContingentGroup' => [ // controller name
            'index' => 'list',    // action name => privilege name
            'detail' => 'detail',
        ],
    ],
];
```

Sync it during installation:

```php
Shopware\B2B\AclRoute\Framework\AclRoutingUpdateService::create()
    ->addConfig($myAclConfig);
```

Translation snippets for resources are prefixed `_acl_` (e.g. resource `contingentgroup` needs `_acl_contingentgroup`).

The config can be autogenerated by `Shopware\B2B\AclRoute\Framework\RoutingIndexer::generate(...)`, which produces entries with placeholder value `NOT_MAPPED` for unmapped resources/privileges that must be filled in manually.

Templates hide inaccessible actions using the `b2b_acl()` twig function:

```twig
<a href="{{ url(...) }}" class="{{ b2b_acl('b2broleaddress', 'assign') }}">
```

This adds CSS classes like `is--b2b-acl-allowed` or `is--b2b-acl-forbidden`; the default behavior hides the element via `display: none`. Applied to a `form`, it removes the submit button and disables form items; applied to a grid table row, it mutes the ajax panel action.

Default privileges: `list`, `detail`, `create`, `delete`, `update`, `assign`, `free`.

## Essential identifiers
- `Shopware\B2B\AclRoute\Framework\AclRoutingUpdateService`
- `Shopware\B2B\AclRoute\Framework\RoutingIndexer`
- `b2b_acl()` twig function
- `_acl_` snippet prefix

## Gotchas
An unmapped route appears as resource/privilege `NOT_MAPPED` in the generated config and must be corrected to the real privilege name before use.
