## What it is

This ADR documents the decision to replace a single fixed-version changelog file with per-change markdown files, autogenerated into the release changelog and upgrade files during the build process.

## When to use

Consult when adding a new feature, deprecation, breaking change, or database migration and deciding whether (and how) to write a changelog entry.

## Key steps / config

- For every feature or important code change, add a changelog markdown file in `/changelog/_unreleased` named `{YYYY-MM-DD}-Meaningful-title-of-the-change.md`. Use `bin/console changelog:create [<title>] [options]` to create one (see `--help` for options).
- File content follows the template in `/changelog/_template.md` (a full example is in `/changelog/_example.md`) and includes meta information: `title` (required), `issue` (required, the Jira key), `flag` (feature flag, if any — flagged files are excluded from a release), `author` and `author_email` (required for external developers), `author_github` (optional).
- Changelog entries are organized under first-class headlines: Core, API, Administration, Storefront, Upgrade Information. Each list entry (except upgrade info) must start with one of: Added, Removed, Changed, Deprecated — "Fixed" is not an allowed keyword.
- On release, files in `/changelog/_unreleased` (excluding flagged ones) move to a new `/changelog/release-6-x-x-x` directory; `/CHANGELOG.md` is updated with links to each entry, and a major/minor `UPGRADE-6.x.md` file is generated or updated with the full Upgrade Information content.
- To generate a changelog for a specific version or part of Shopware, use `bin/console changelog:change [<version>] [options]`.

## Essential identifiers

`bin/console changelog:create`, `bin/console changelog:change`, `/changelog/_unreleased`, `/changelog/_template.md`, `/changelog/_example.md`, `/CHANGELOG.md`, `UPGRADE-6.x.md`

## Gotchas

Entries must use one of the required keywords (Added, Removed, Changed, Deprecated) rather than a vague word like "Fixed" — e.g. "Changed method `registerCmsElement()` in `module/sw-cms/service/cms.service.js`..." rather than "Fixed data binding issues in CMS elements."
