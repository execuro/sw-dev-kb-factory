## What it is
Architecture decision record establishing that, since Shopware 6.5 requires PHP 8.1, new code representing lists of constant values should use PHP Enums instead of class constants.

## When to use
Relevant when adding new constant-value lists (e.g. product types, statuses) or migrating existing constant-based APIs to enums without breaking consumers.

## Key steps / config
Migration follows the Expand & Contract pattern in four steps:
1. Create the enum and accept it alongside the string in the API, keeping both constants and enum in sync:
```php
enum IndexMethod
{
    case PARTIAL;
    case FULL;
}
class Indexer
{
    public function product(int $id, IndexMethod|string $method): void { ... }
}
```
2. Convert incoming primitive values to the enum internally (via `match` or `BackedEnum::from` if backed).
3. Mark the constants and the string-accepting parameter as `@deprecated tag:v6.6.0`.
4. Remove the deprecated constants/string support in the next major, leaving only:
```php
class Indexer
{
    public function product(int $id, IndexMethod $method): void { ... }
}
```

## Essential identifiers
- `IndexMethod` enum (example)
- `BackedEnum::from`
- `@deprecated tag:v6.6.0`

## Gotchas
In PHP 8.1 an enum case cannot be assigned directly to a class constant (`public const PARTIAL = IndexMethod::PARTIAL->value;` needs PHP 8.2 backed enums). Examples given for enum candidates: product types (Parent, Variant), product status (Enabled, Disabled), backup type (Full, Incremental).
