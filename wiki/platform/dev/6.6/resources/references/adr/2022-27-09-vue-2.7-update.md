## What it is

ADR documenting Shopware 6 Administration's decision to skip the Vue 2.7 release and go directly to Vue 3 in the next major version, instead of upgrading the Vue 2 line first.

## When to use

Relevant when planning Administration framework upgrades, or when trying to understand why the Vue version used in the admin skips 2.7 and jumps straight to Vue 3.

## Key steps / config

- Context: Vue 2.7 backports some Vue 3 features, including the Composition API. This ADR explains why Shopware does not upgrade to Vue 2.7 before its next major version.
- Decision: skip Vue 2.7 and move directly to Vue 3 the following year, because the work required to adopt 2.7 outweighs its benefits.
- Work that would be required to adopt Vue 2.7 (and that is therefore skipped): updating the Component Factory to support the Composition API, including deciding whether and how to make that API extendable; fixing runtime errors that freeze the whole admin, caused partly by reliance on internal Vue code; rewriting the TypeScript definitions for components to match Vue 2.7's improved typings for Mixins and `extend`, complicated by wrapper abstractions like the Mixin Factory needing to return correct types for TypeScript to keep working.
- Consequence: Shopware does not update to Vue 2.7 and jumps directly to Vue 3.

## Essential identifiers

- Vue 2.7, Vue 3
- Component Factory
- Composition API
- Mixin Factory

## Gotchas

The ADR frames this as "much work for a short time and no real benefits" if the Composition API is not exposed for extensibility — the migration cost applies for only one major version before Vue 3 replaces it anyway, which is the stated reason for skipping 2.7 rather than doing both upgrades.
