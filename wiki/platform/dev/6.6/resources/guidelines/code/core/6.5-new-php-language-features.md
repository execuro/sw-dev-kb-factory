## What it is

Since Shopware 6.5, the minimum PHP version is 8.1 and minimum Symfony version is 6.1; this guideline promotes the new language features developers should use going forward.

## When to use

Reference this when writing or reviewing PHP code in Shopware core to decide which modern PHP/Symfony construct to use instead of older boilerplate.

## Key steps / config

Promoted properties replace repetitive constructor boilerplate:

```php
class Point {
    public function __construct(private int $x, private int $y) {}
}
```

`match` replaces `switch` for exhaustive, strictly-compared branching and throws `UnhandledMatchError` if nothing matches and there is no default arm. New string functions `str_contains`, `str_starts_with`, `str_ends_with` replace `strpos`-based checks. Named arguments (e.g. `htmlspecialchars($string, double_encode: false)`) should only be used when calling PHP APIs, not Shopware APIs, since parameter names are not covered by the BC promise. Union (`int|string`), intersection (`MyService&MockObject`), and `mixed` types should be used natively instead of `@var`/`@param` annotations except for array shapes, generics, and types like `class-string`. Enums (`enum IndexMethod { case PARTIAL; case FULL; }`) replace constant lists used for validity checks. Readonly properties (`public readonly int $productId`) build immutable DTOs. First-class callable syntax (`strlen(...)`, `$object->doCoolStuff(...)`) replaces string/array callables. Native attributes (`#[Route('/blog', name: 'blog_list')]`) replace PHP docblock annotations such as `@Route`. The nullsafe operator (`$user?->address?->addressLine2`) short-circuits a chained access instead of nested null checks.

Symfony 6.1 additions: enum-validated route parameters via `EnumRequirement`; service autowiring via the `#[Autowire(service: '...')]` / `#[Autowire('%kernel.debug_mode%')]` attributes instead of XML; and console autocompletion values as the 5th `addArgument()` parameter.

## Essential identifiers

- `str_contains`, `str_starts_with`, `str_ends_with`
- `match` expression, `UnhandledMatchError`
- `#[Route(...)]`, `#[Autowire(service: ...)]`
- Nullsafe operator `?->`
- First-class callable syntax `(...)`
- `never` return type, `array_is_list()`, `final const`, `$object::class`

## Gotchas

- Migrating `switch` to `match` can be a BC break: `switch` performs loose type comparisons while `match` uses strict equality, so values and case coverage must be re-checked.
- Named parameters should only be used against PHP's own APIs, never Shopware's, since Shopware's parameter names are not part of the backward compatibility promise.
- New `readonly` on public/protected properties of existing code is a BC break; only private properties never written to after construction can be safely migrated to `readonly`.
