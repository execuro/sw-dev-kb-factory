## What it is

This page explains how to load-test a Shopware store's performance using K6, a load testing tool that runs JavaScript scenarios simulating concurrent users.

## When to use

Use it to measure how a Shopware store performs under simulated load before going live or after infrastructure/config changes.

## Key steps / config

Prerequisites: a Shopware store, K6 installed locally, and Bun. Set up:

```bash
git clone https://github.com/shopware/k6-shopware.git
cd k6-shopware
bun install
cp .env.example .env
bun run fetch-fixtures.ts
```

On the Shopware side: disable captcha on login/register, disable email sending (Admin -> Settings -> System -> Mailer), and seed data if needed:

```bash
APP_ENV=prod php bin/console framework:demodata
APP_ENV=prod php bin/console dal:refresh:index
```

For more products: `framework:demodata --reset-defaults --products=5000` (can run in parallel; run `dal:refresh:index` after all finish).

Run a scenario file:

```bash
k6 run example.js
```

Scale virtual users/iterations:

```bash
k6 run --vus 10 --iterations 100 example.js
```

Multiple named scenarios are defined in an `options.scenarios` object (e.g. `executor: 'constant-vus'`, `vus`, `duration`, `exec`) and cannot be combined with CLI `--vus`/`--iterations`.

Enable the live dashboard:

```bash
K6_WEB_DASHBOARD=true k6 run --vus 10 --duration 5m example.js
```

then open the dashboard UI in a browser. K6 Cloud (via an API token from grafana.com) allows distributing load across locations with detailed Grafana reports.

## Essential identifiers

- `k6-shopware` repository
- `fetch-fixtures.ts`
- `framework:demodata`, `dal:refresh:index`
- `K6_WEB_DASHBOARD`
- `k6 run --vus --iterations`

## Gotchas

When testing against production, inform the hosting provider first — the test IP may get rate-limited or blocked, producing false positives; Grafana Cloud is recommended to distribute load across locations.
