## What it is
Explains how to react to order changes (line items or order states changing) by subscribing to order-related events and, when needed, forcing generation of a write changeset.

## When to use
Use when a plugin needs to run logic whenever an order entity is written/changed, especially when it needs to know exactly what changed (before/after values), not just that a write happened.

## Key steps / config
1. Find relevant events in the `Shopware\Core\Checkout\Order\OrderEvents` class; general order changes fire `OrderEvents::ORDER_WRITTEN_EVENT`.
2. Implement `Symfony\Component\EventDispatcher\EventSubscriberInterface`, subscribe to `OrderEvents::ORDER_WRITTEN_EVENT`, and in the handler check `$event->getContext()->getVersionId() !== Defaults::LIVE_VERSION` to skip non-live (draft) versions.
3. A changeset is not generated by default for performance reasons. To force one, additionally subscribe to `Shopware\Core\Framework\DataAbstractionLayer\Write\Validation\PreWriteValidationEvent` (fired before the write result set is generated). In that handler, iterate `$event->getCommands()`, filter for `ChangeSetAware` commands, check `$command->getEntityName() !== OrderDefinition::ENTITY_NAME`, and call `$command->requestChangeSet()`.
4. Back in the `ORDER_WRITTEN_EVENT` handler, read the changeset via `$result->getChangeSet()` for each entry in `$event->getWriteResults()`.

## Essential identifiers
- `Shopware\Core\Checkout\Order\OrderEvents::ORDER_WRITTEN_EVENT`
- `Shopware\Core\Framework\DataAbstractionLayer\Write\Validation\PreWriteValidationEvent`
- `Shopware\Core\Framework\DataAbstractionLayer\Write\Command\ChangeSetAware`
- `Shopware\Core\Framework\DataAbstractionLayer\Event\EntityWrittenEvent`
- `Shopware\Core\Checkout\Order\OrderDefinition::ENTITY_NAME`
- `Shopware\Core\Defaults::LIVE_VERSION`
- `requestChangeSet()`, `getChangeSet()`

## Gotchas
An "insert" command cannot generate a changeset since nothing changed yet. Only cover the live version: editing an order in the admin creates a new draft version that later merges into the live version on save, which is usually not the state to react to. Generating changesets impacts performance, so narrow the entity check as much as possible.

## Version notes
Before Shopware 6.6.3.0, use `$command->getDefinition()->getEntityName()` instead of `$command->getEntityName()`.
