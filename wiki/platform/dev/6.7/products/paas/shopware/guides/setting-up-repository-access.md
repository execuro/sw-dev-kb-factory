## What it is

How Shopware PaaS Native gets read access to a private Git repository: an SSH deploy key whose private half is stored in the PaaS Vault and whose public half is added to the repository. The platform uses it to clone the code during deployments. Whichever setup path you choose, the public key must be added to the repository.

## When to use

When onboarding a project whose code lives in a private GitHub, GitLab or Bitbucket repository, or when replacing/rotating the deploy key.

## Key steps / config

Option 1 — automated via the PaaS CLI:

```sh
sw-paas vault create --type ssh                         # organization level (default)
sw-paas vault create --type ssh --project <project-id>  # limit to one project
```

The default stores the key at the organization level, available to all projects in the org; `--project` restricts it to one project. Copy the generated public key and add it to the repository's Deploy keys section.

Option 2 — manual setup:

1. Generate a passwordless key pair, private key in PEM format:
   ```bash
   ssh-keygen -t rsa -b 4096 -m PEM -f ./sw-paas
   ```
   ED25519 and ECDSA also work, provided the key is passwordless and the private key is PEM.
2. Copy the contents of `sw-paas.pub` and add it as a **read-only** deploy key: GitHub → repository `Settings` → `Deploy keys`; GitLab/Bitbucket have an equivalent "Deploy keys" section. Enable read-only access.
3. Store the private key in the Vault:
   ```bash
   cat sw-paas | sw-paas vault create --type ssh --password-stdin
   ```

## Essential identifiers

- `sw-paas vault create --type ssh` (options `--project <project-id>`, `--password-stdin`)
- `ssh-keygen -t rsa -b 4096 -m PEM -f ./sw-paas`, public key file `sw-paas.pub`
- Key levels: organization (shared across projects) and project (dedicated to one project)

## Gotchas

- Only one SSH key can be stored per level (organization or project). The key name is free, but a project-level key overrides the organization-level key during deployments.
- The key must be passwordless and the private key must be PEM-formatted, whatever algorithm is used.
- Give the deploy key read-only access in the Git host.
