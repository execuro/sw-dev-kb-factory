## What it is

How to customize the internationalization (i18n) setup of the Sales Agent Nuxt 3 frontend using the Nuxt layer concept, so that you extend or override the default translations without modifying core files.

## When to use

When you need to change existing texts, override translations for a language, or adjust the locale configuration of the Sales Agent.

## Key steps / config

All paths refer to your customization layer folder.

1. Configure i18n in your layer's `nuxt.config.ts`. It defines the language directory and the language configurations you want to override:

```js
modules: ["@nuxtjs/i18n"],
i18n: {
  langDir: "./i18n/src/langs/",
  locales: [
    { code: "en-GB", iso: "en-GB", file: "en-GB.ts" },
    { code: "de-DE", iso: "de-DE", file: "de-DE.ts" },
  ],
},
```

2. Create the i18n folder structure in your custom layer, mirroring the structure of the default layer — but only create the files you actually need to override.
3. Use the `example` layer in the source code as the reference for the folder structure.

## Essential identifiers

- `@nuxtjs/i18n` — Nuxt module to register in `modules`
- `i18n.langDir` — `./i18n/src/langs/`
- `i18n.locales` — entries with `code`, `iso`, `file` (`en-GB.ts`, `de-DE.ts`)
- `nuxt.config.ts` — config file inside your layer

## Gotchas

- Mirror the default layer's paths exactly; only the files you create are overridden, the rest keep coming from the default layer.
