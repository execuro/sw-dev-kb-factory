## What it is

Process ADR (status: accepted) that supersedes the 2020 changelog ADR `2020-08-03-implement-new-changelog.md` (archived under `adr/_superseded/`). Instead of per-change markdown files under `/changelog/_unreleased` aggregated into `CHANGELOG.md` and `UPGRADE.md`, Shopware uses curated in-repo release files plus an automatically generated raw changelog.

## When to use

- When contributing a PR to the Shopware repository and deciding where to document a developer-facing change or a breaking change.
- When looking for the authoritative developer-facing release notes or upgrade instructions of a Shopware version.

## Key steps / config

Curated files:

- `RELEASE_INFO-6.<currentMajor>.md` — developer-facing release notes, one section per minor; new entries go into the "Upcoming" section.
- `UPGRADE-6.<upcomingMajor>.md` — upgrade instructions and breaking changes.

Entry shape (category, concise description, PR reference):

```
## 6.7.5 (Upcoming)
### Core
- <description> (PR #<number>)
### Administration
- <description> (PR #<number>)
```

An `UPGRADE-6.8.md` entry is a short heading per deprecated/changed item, followed by what changed and how plugins should migrate; sub-headings such as "What changed" / "How to adjust" are optional.

PR author workflow:

1. Information that benefits external developers goes into `RELEASE_INFO-6.X.md` (Upcoming section).
2. Breaking changes go into `UPGRADE-6.Y.md`.
3. Reviewers verify consistency and readability; CI does not enforce a strict format initially.
4. The PR template references this process with checklist guidance.

Autogenerated changelog:

- The full changelog per release is generated automatically from merged PRs and commits and linked from the release notes.
- It is grouped by labels (e.g. `bug`, `feature`, `performance`) and links PRs and authors; intended for engineering, support and partners.

## Essential identifiers

- `RELEASE_INFO-6.<minor>.md` / `RELEASE_INFO-6.7.md`
- `UPGRADE-6.<major>.md` / `UPGRADE-6.8.md`
- `adr/_superseded/2020-08-03-implement-new-changelog.md`
- PR labels `bug`, `feature`, `performance`

## Gotchas

- Per-change files in `/changelog/_unreleased` are no longer the workflow for developer-facing notes.
- Marketing and Comms pull content only from `RELEASE_INFO` and `UPGRADE`, never from the raw changelog; reviewers must ensure entries are added or explicitly marked unnecessary.
- The source's `UPGRADE-6.8.md` example names `SalesChannelContextSwitcher` migrating to `ContextResolverInterface`; this is illustrative only — in the installed code the class is deprecated with a pointer to `AbstractContextSwitchRoute` (see Code check).
