## What it is

Architecture decision record (area: core, stock) that replaced the old stock/available-stock calculation with a single realtime `stock` value on `product` and an extensible stock storage API. `stock` is decremented when an order is placed, incremented on cancellation, and so on through the order lifecycle.

## When to use

- Loading stock from an external system (ERP, multi-warehouse) instead of the `product` table.
- Changing how stock is increased/decreased during the order lifecycle.
- Disabling Shopware's built-in stock handling entirely.

## Key steps / config

1. Decorate `Shopware\Core\Content\Product\Stock\AbstractStockStorage` (default implementation `Shopware\Core\Content\Product\Stock\StockStorage`). A subclass declares all four abstract methods:

```php
class MyStockStorage extends AbstractStockStorage
{
    public function getDecorated(): AbstractStockStorage { /* ... */ }
    public function load(StockLoadRequest $stockRequest, SalesChannelContext $context): StockDataCollection { /* ... */ }
    /** @param list<StockAlteration> $changes */
    public function alter(array $changes, Context $context): void { /* ... */ }
    /** @param list<string> $productIds */
    public function index(array $productIds, Context $context): void { /* ... */ }
}
```

2. `load()` augments products loaded in the storefront/store API: values from `StockData` (`stock`, `available`, optional `minPurchase`, `maxPurchase`, `isCloseout`) overwrite the product's values, and the data is added as extension `stock_data`. Called from `LoadProductStockSubscriber` and `AvailableCombinationLoader`.
3. `alter()` receives a list of `StockAlteration` DTOs, one per line item change: `lineItemId`, `productId`, `quantityBefore`, `newQuantity`; `quantityDelta()` returns `quantityBefore - newQuantity`. The core `StockStorage` updates `product.stock` directly by the delta.
4. `index()` is called by `ProductIndexer` with changed product IDs, e.g. to update the `available` flag.
5. `OrderStockSubscriber` holds all internal stock business rules. It listens to `EntityWriteEvent` (order line item writes: order placed, item added/removed, quantity changed, product changed) and `StateMachineTransitionEvent` (order cancelled → stock increased; reopened from cancelled → decreased), and calls `alter()`.
6. Disable built-in handling in config (default `true`):

```yaml
shopware:
    stock:
        enable_stock_management: false
```

7. `availableStock` on `ProductDefinition` is kept only as a mirror: `AvailableStockMirrorSubscriber` (on `EntityWriteEvent`) copies `stock` into `available_stock`.
8. Variant availability: `AbstractAvailableCombinationLoader::loadCombinations(string $productId, SalesChannelContext $salesChannelContext): AvailableCombinationResult` is abstract; `ProductConfiguratorLoader` calls it.

## Gotchas

- The ADR refers to `Shopware\Core\Content\Product\DataAbstractionLayer\AbstractStockStorage` and `Shopware\Core\Content\Product\DataAbstractionLayer\StockUpdater`; neither exists in 6.7. The storage lives in the `Stock` namespace; `StockUpdater` (including `updateAvailableStockAndSales`) is gone.
- The ADR's `BeforeWriteEvent` was implemented as `EntityWriteEvent` (with `addSuccess`/`addError` callbacks).
- The ADR's `STOCK_HANDLING` feature flag no longer exists; the new behaviour is always active since 6.6.
- Stock loading moved from `ProductSubscriber::salesChannelLoaded` to `LoadProductStockSubscriber::salesChannelLoaded`.
- `AbstractStockUpdateFilter` and `StockUpdateFilterProvider` were announced for removal in 6.6 but still exist in 6.7.13 without a `@deprecated` tag.
- To replace the whole logic, disable `OrderStockSubscriber` via the config flag and implement your own solution.
- Every `AbstractStockStorage` implementation must handle all scenarios: order placed, cancelled, cancelled→open, line item added/removed/quantity changed/product changed, non-cancelled order deleted.

## Version notes

In 6.5 the new handling was opt-in via a feature flag and `StockUpdater` was deprecated; from 6.6 the new API is the default and the old classes are removed.
