## What it is

Architecture decision record (2023) that replaced Shopware's two-value stock model (`stock` plus a computed `available_stock`) with a single real-time `stock` value, and introduced an extensible stock storage API in the namespace `Shopware\Core\Content\Product\Stock`. Order lifecycle events are translated into stock changesets and handed to a stock storage implementation; projects can decorate that storage (e.g. to talk to an ERP or multi-warehouse inventory) or switch Shopware's own stock handling off.

## When to use

- You need to replace stock loading or stock updates with a custom implementation (ERP sync, multi-warehouse).
- You need to know how stock reacts when an order is placed, cancelled, reopened, deleted, or its line items change.
- You want to disable Shopware's built-in stock management entirely.

## Key steps / config

1. Extend `Shopware\Core\Content\Product\Stock\AbstractStockStorage` (or decorate the core `Shopware\Core\Content\Product\Stock\StockStorage`). Every subclass declares all four abstract members:

```php
class MyStockStorage extends AbstractStockStorage
{
    public function getDecorated(): AbstractStockStorage { /* ... */ }
    public function load(StockLoadRequest $stockRequest, SalesChannelContext $context): StockDataCollection { /* ... */ }
    /** @param list<StockAlteration> $changes */
    public function alter(array $changes, Context $context): void { /* ... */ }
    /** @param list<string> $productIds */
    public function index(array $productIds, Context $context): void { /* ... */ }
}
```

2. `load()` returns a `StockDataCollection` (`add()`, `getStockForProductId()`, `all()`) of `StockData` structs (`productId`, `stock`, `available`, optional `minPurchase`, `maxPurchase`, `isCloseout`). The values are set directly on the loaded products and the struct is added as product extension `stock_data`. Called from `LoadProductStockSubscriber` and `AvailableCombinationLoader`.
3. `alter()` receives a list of `StockAlteration` objects (`lineItemId`, `productId`, `quantityBefore`, `newQuantity`, `quantityDelta()`), one per line item change.
4. `index()` runs when products are created/updated, e.g. to recompute the `available` flag.
5. Disable built-in stock handling with the config key `shopware.stock.enable_stock_management: false` (default `true`); `OrderStockSubscriber` then returns early for all events.

`OrderStockSubscriber` holds all internal stock business rules. It listens to `EntityWriteEvent` (order placed, line item added/removed, quantity changed, product swapped) and `StateMachineTransitionEvent` (to/from `OrderStates::STATE_CANCELLED`). Changesets per scenario: order placed/reopened or item added: before 0, new = ordered qty; cancelled or item removed: before = ordered qty, new 0; qty update: old and new qty; product changed: two changes (old product to 0, new product from 0). A non-cancelled order being deleted restores its stock.

`AvailableStockMirrorSubscriber` copies any `stock` write into `available_stock`; `availableStock` is kept as a write-protected mirror of `stock`, deprecated with no removal plan.

Variant combinations are loaded via `AbstractAvailableCombinationLoader::loadCombinations(string $productId, SalesChannelContext $salesChannelContext): AvailableCombinationResult`, which `ProductConfiguratorLoader` calls.

## Gotchas

- The ADR places the storage and `StockUpdater` in `Shopware\Core\Content\Product\DataAbstractionLayer\` (e.g. `Shopware\Core\Content\Product\DataAbstractionLayer\AbstractStockStorage`); neither exists there. The real class lives in `...\Product\Stock\`, and `StockUpdater` is gone.
- The ADR's `BeforeWriteEvent` does not exist in 6.7; the pre-write event with `addSuccess`/`addError` callbacks is `EntityWriteEvent` (callbacks typed `callable`, not `\Closure`).
- `OrderStockSubscriber` is wired to the concrete `StockStorage` service, so a custom implementation must decorate `StockStorage` to receive `alter()` calls.
- `StockStorage::alter()` only acts in the live version and adds `quantityDelta()` (before minus new) to `stock`, adjusting `sales` and setting `available_stock = stock`.
- The ADR said stock update filters (`AbstractStockUpdateFilter`, `StockUpdateFilterProvider`) would be removed in 6.6; both classes are still present in 6.7.

## Version notes

- The `STOCK_HANDLING` opt-in feature flag was for 6.5; the new behaviour became the default in 6.6 and the flag no longer exists.
- `AbstractAvailableCombinationLoader::load()` was deprecated for 6.6; in 6.7 `loadCombinations()` is abstract.
