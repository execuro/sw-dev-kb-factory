## What it is

An architecture decision record (2022) explaining why the Shopware Administration did not upgrade to Vue 2.7 (which backported Vue 3 features such as the Composition API) and instead planned to move directly to Vue 3.

## When to use

When you need background on the Administration's Vue migration path, or why Composition API support was not introduced on Vue 2.

## Key steps / config

Work that a Vue 2.7 update would have required, per the ADR:

- Fix and update the Component Factory to support the Composition API — including deciding whether that API should be extendable and, if so, designing and implementing the extension concept.
- Fix many runtime errors that freeze the whole Administration, caused among other things by use of internal Vue code.
- Rewrite the TypeScript definitions for Administration components to match Vue 2.7's improved typings (now covering Mixins, Extend, etc.); wrappers like the Mixin Factory must return correct types or components break under TypeScript.

Decision: the effort would only serve one major version before Vue 3, with no real benefit unless the Composition API were allowed, so Vue 2.7 was skipped.

## Gotchas

- The ADR describes a Vue 2-era Administration. The installed 6.7 Administration already runs on Vue 3: its view adapter imports `createApp` from `vue`.

## Version notes

- Consequence of the ADR: no Vue 2.7 release; the Administration moved straight to Vue 3 (present in 6.7).
