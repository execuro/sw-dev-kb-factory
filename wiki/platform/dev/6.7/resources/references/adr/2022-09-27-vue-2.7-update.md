## What it is

An architecture decision record (2022-09-27, area administration) explaining why the Shopware Administration did not upgrade to Vue 2.7 — the release that backported Vue 3 features such as the Composition API — and instead planned a direct jump to Vue 3 the following year.

## When to use

When you need the rationale for the Administration's Vue version history, or wonder why there was never a Vue 2.7 based Administration between the Vue 2 and Vue 3 majors.

## Key steps / config

The ADR is a decision, not a how-to. Its reasoning: the effort outweighs the benefit, because the work would only serve one major version before Vue 3. Updating to 2.7 would have required:

1. Fixing and updating the Component Factory to support the Composition API — including deciding whether that API should be extendable and, if so, designing and implementing the extension concept.
2. Fixing many runtime errors that freeze the whole Administration, caused among other things by use of internal Vue code.
3. Rewriting the TypeScript definitions of the components for Vue 2.7's improved typings (which now cover Mixins, Extend, etc.). The hard part is Shopware's wrappers such as the Mixin Factory, which must return correct types or components break under TypeScript.

Consequence: no Vue 2.7 update; go directly to Vue 3.

## Essential identifiers

- Component Factory — in 6.7 `src/core/factory/async-component.factory.ts` (`register`, `extend`, `override`)
- Mixin Factory — `src/core/factory/mixin.factory.ts`
- Vue view adapter — `src/app/adapter/view/vue.adapter.ts` (bootstraps the app with Vue 3 `createApp`)

## Version notes

- In 6.7 the Administration runs on Vue 3: the view adapter imports `createApp`, `defineAsyncComponent` and `h` from `vue`.
- The extendability question the ADR raises for the Composition API is answered in 6.7 by an adapter module `src/app/adapter/composition-extension-system/index.ts` and an `options-composition-shim.ts`; the ADR itself predates them.
