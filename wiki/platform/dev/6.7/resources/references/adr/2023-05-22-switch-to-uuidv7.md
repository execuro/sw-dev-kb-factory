## What it is

Architecture decision record (2023-05-22, area core, tag DAL): Shopware switched the IDs generated by its `Uuid` class from random UUIDv4 to time-based UUIDv7.

## When to use

When reasoning about primary key generation, index size or insert performance in the DAL, or when wondering why newly generated Shopware IDs share a time-based prefix.

## Key steps / config

- UUIDs are used as primary keys because they ease integrating different data sources.
- UUIDv4 has a completely random prefix, which makes database B-tree indexes inefficient.
- UUIDv7 has a time-based prefix that is less spread, so the index allocates fewer new pages and stays smaller.
- v4 and v7 share the same length and are indistinguishable for Shopware, so the switch carries no breaking risk.
- The effort is low: only the implementation of `Shopware\Core\Framework\Uuid\Uuid` changed. In 6.7 `Uuid::randomBytes()` builds the bytes with Ramsey's `UnixTimeGenerator` and applies version 7; `Uuid::randomHex()` hex-encodes that result.
- IDs remain 32-character lowercase hex strings (`Uuid::VALID_PATTERN` is `^[0-9a-f]{32}$`); validation does not check the UUID version.
- Measured gain cited by the ADR: about 8 % faster bulk product inserts.

## Essential identifiers

- `Shopware\Core\Framework\Uuid\Uuid`
- `Uuid::randomHex()`, `Uuid::randomBytes()`
- `Uuid::VALID_PATTERN`

## Version notes

Consequence stated by the ADR: UUIDv7 becomes the default, and performance guides promote v7.
