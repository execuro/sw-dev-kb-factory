## What it is

Core coding guideline (dated 2023-05-16, Shopware 6.5) that promotes PHP 8.0/8.1 and Symfony 6.1 language features in Shopware code, with for each feature the advantages and whether migrating existing code is a backward-compatibility (BC) break.

## When to use

When writing or refactoring Shopware core or plugin PHP code and deciding which modern syntax to use, or whether converting existing code (switch to match, properties to readonly, constants to enums) breaks BC.

## Key steps / config

**PHP 8.0 / 8.1 features**

- **Promoted properties** — declare properties in the constructor: `public function __construct(private int $x, private int $y) {}`. Core was refactored with Rector. Not a BC break.
- **New in initializers** — object default values: `private Hasher $hasher = new Bcrypt()`. Not a BC break.
- **`match`** instead of `switch` — strict comparison, no fall-through, is an expression, throws `UnhandledMatchError` if no arm matches and no `default`. Core refactored with Rector.
- **String functions** — `str_contains`, `str_starts_with`, `str_ends_with` instead of `strpos`/`strlen` checks.
- **Named arguments** — e.g. `htmlspecialchars($string, double_encode: false);`; most useful with self-undescriptive values (`true`, `false`, `0`, `[]`, `null`). Allowed for Shopware and PHP APIs.
- **Native types** — use `mixed`, union (`int|string`) and intersection (`MyService&MockObject`) types; reserve `@var`/`@param` for array shapes, generics, `class-string`, `positive-int`.
- **Enums** — replace constant lists and validation arrays; combine with `match`; backed enums support `MyEnum::from()` / `MyEnum::tryFrom()`.

```php
enum IndexMethod { case PARTIAL; case FULL; }

public function product(int $id, IndexMethod $method): void
{
    match ($method) {
        IndexMethod::PARTIAL => $this->partial($id),
        IndexMethod::FULL => $this->full($id),
    };
}
```

- **Readonly properties** — for DTOs: `public function __construct(public readonly int $productId, public readonly bool $includeStock) {}`.
- **First-class callables** — `strlen(...)`, `$object->doCoolStuff(...)`, `\My\Object::doCoolStuff(...)` instead of string/array callables.
- **Attributes** instead of docblock annotations, e.g. `#[Route('/blog', name: 'blog_list')]`; core converted with Rector.
- **Nullsafe operator** — `$user?->address?->addressLine2`.
- Other: `never` return type, `array_is_list`, `final const`, `$object::class`, array unpacking with string keys.

**Symfony 6.1 features**

- Enum route requirements: `requirements: ['bar' => new EnumRequirement(SomeEnum::class)]` (`Symfony\Component\Routing\Requirement\EnumRequirement`).
- Autowiring attributes (`Symfony\Component\DependencyInjection\Attribute\Autowire`): `#[Autowire(service: 'email_adapter')]`, `#[Autowire('%kernel.debug_mode%')]` on constructor parameters; service decoration via attributes is also possible.
- Console autocompletion: pass a closure as the 5th argument of `addArgument()`, e.g. `fn () => self::availableFeatures()`.

## Essential identifiers

- `match`, `UnhandledMatchError`, `enum`, `readonly`, `mixed`
- `str_contains`, `str_starts_with`, `str_ends_with`, `array_is_list`
- `Symfony\Component\Routing\Requirement\EnumRequirement`
- `Symfony\Component\DependencyInjection\Attribute\Autowire`
- `#[Route]`

## Gotchas

- Replacing `switch` with `match` can break BC: `switch` compares loosely and does not throw for unhandled values — verify value types and cover all cases.
- Private properties not written after instantiation can become `readonly` without BC break; making existing public/protected properties `readonly` is a BC break (fine for new code).
- Named arguments couple callers to parameter names; renames of supported API are announced ahead for the next major, positional calls are unaffected.
- The source's attribute example imports `Symfony\Component\Routing\Annotation\Route`; installed core imports `Symfony\Component\Routing\Attribute\Route`.
- The "From" example of `PasswordHasher` in the source declares `$hasher` twice (property and promoted parameter) — illustrative only.

## Version notes

- The guideline states PHP 8.1 / Symfony 6.1 minimums for 6.5. Installed core 6.7.13 requires PHP `~8.2.0 || ~8.3.0 || ~8.4.0 || ~8.5.0` and `symfony/framework-bundle` `~7.4.0`, so all listed features are available.
