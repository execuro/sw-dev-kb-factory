## What it is

What to do once the [development environment](platform/dev/6.7/guides/development/dev-environment.md) containers run: console and Composer commands, frontend watchers, environment customization and private Composer packages.

## When to use

Daily work on a Docker-based Shopware project managed by Shopware CLI.

## Key steps / config

**Environment**: Storefront on `127.0.0.1` port `8000`, Administration at `/admin` (default credentials `admin` / `shopware`). The development TUI (`shopware-cli project dev`) shows both. Plugins/themes live in `custom/`.

**Console commands** from the host (routed into the web container):

```bash
shopware-cli project console cache:clear
shopware-cli project console plugin:install --activate MyPlugin
shopware-cli project console database:migrate --all
```

**Composer**: no CLI wrapper; run inside the `web` container: `docker compose exec web bash`, `docker compose exec web composer require some/package`.

**Frontend watchers** (also from the DevTUI Overview tab, key `1`; see [Using Watchers](platform/dev/6.7/guides/development/tooling/using-watchers.md)):

```bash
shopware-cli project admin-watch          # Vite HMR, port 5173
shopware-cli project storefront-watch     # webpack HMR, port 9998
shopware-cli project admin-watch --only-extensions MyPlugin,OtherPlugin
shopware-cli project admin-watch --skip-extensions SomePlugin
shopware-cli project storefront-build --only-custom-static-extensions
shopware-cli project admin-build --only-custom-static-extensions
```

**Customization**: `compose.yaml` is regenerated by shopware-cli; put changes in `compose.override.yaml`:

```yaml
services:
  web:
    environment:
      APP_ENV: dev
    ports: ["9003:9003"]      # Xdebug
  database:
    ports: ["3306:3306"]      # expose MySQL
```

- Remote DB: `DATABASE_URL="mysql://user:password@<host>:3306/<database>"` in `.env.local`; if `localhost` is unreachable, use `host.docker.internal` or the host LAN IP.
- `.env` overrides defaults; changing `APP_ENV` needs `shopware-cli project dev stop && shopware-cli project dev start`.

**Private Composer packages** (licensed extensions), token from Shopware account **Shops > Licenses**:

```bash
docker compose exec web composer config --auth http-basic.packages.shopware.com <username> <token>
docker compose exec web composer require <package>
```

**First Administration login**: sign in to a Shopware account (needed for Store extensions), connect the Store, install extensions, configure payment methods. Shop basics: **Settings > Shop > Basic information**.

## Essential identifiers

- `shopware-cli project console`, `shopware-cli project dev`, `admin-watch`, `storefront-watch`, `--only-extensions`, `--skip-extensions`, `--only-custom-static-extensions`
- `compose.override.yaml`, `.env.local`, `DATABASE_URL`, `APP_ENV`, `auth.json`

## Gotchas

- Do not run `composer` on the host unless host PHP meets requirements (`memory_limit` at least `512M`, needed extensions); the TUI **Setup health** check reflects container PHP.
- Never edit `compose.yaml`; do not commit `auth.json`.
- The Storefront watcher prompts for a sales channel if none is configured.
- Older make-based setups use `make shell` instead.
