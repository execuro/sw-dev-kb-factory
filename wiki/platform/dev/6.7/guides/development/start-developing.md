## What it is

What to do once the [development environment](platform/dev/6.7/guides/development/dev-environment.md) containers are running: where things are, how to run console/Composer commands, frontend watchers, and environment customization for a Docker-based project managed by Shopware CLI.

## When to use

You have a running Docker setup and need to run `bin/console` commands, start HMR watchers, customize containers, point to another database or install licensed Composer packages.

## Key steps / config

**Environment.** Storefront is served on local port 8000, Administration under `/admin` on the same host (default credentials `admin` / `shopware`). The dev TUI (`shopware-cli project dev`) shows URLs and credentials. Plugins/themes live in `custom/`.

**Console commands** from the host (routed into the web container):

```bash
shopware-cli project console cache:clear
shopware-cli project console plugin:install --activate MyPlugin
shopware-cli project console database:migrate --all
```

**Composer/PHP/npm**: no CLI wrapper yet; run inside the `web` container (container PHP has `memory_limit` >= 512M):

```bash
docker compose exec web bash
docker compose exec web composer require some/package
```

Older make-based setups: `make shell` (or `docker compose exec web bash`).

**Watchers** (start from DevTUI Overview tab, key `1`, or CLI):

```bash
shopware-cli project admin-watch        # Vite HMR, port 5173
shopware-cli project storefront-watch   # webpack HMR, port 9998
shopware-cli project admin-watch --only-extensions MyPlugin,OtherPlugin
shopware-cli project admin-watch --skip-extensions SomePlugin
shopware-cli project storefront-build --only-custom-static-extensions
shopware-cli project admin-build --only-custom-static-extensions
```

The storefront watcher prompts for a sales channel if none is configured. See [Using Watchers](platform/dev/6.7/guides/development/tooling/using-watchers.md).

**Container customization**: `compose.yaml` is regenerated by shopware-cli; put changes in `compose.override.yaml`:

```yaml
services:
  web:
    environment:
      APP_ENV: dev
    ports: ["9003:9003"]    # Xdebug
  database:
    ports: ["3306:3306"]
```

**Remote database**: set `DATABASE_URL="mysql://user:password@<host>:3306/<database>"` in `.env.local`; if the container cannot reach `localhost`, use `host.docker.internal` or the host LAN IP. A project-root `.env` overrides defaults; `APP_ENV` changes need `shopware-cli project dev stop && shopware-cli project dev start`.

**Private Composer packages**: create a token in the Shopware account under **Shops > Licenses**, then:

```bash
docker compose exec web composer config --auth http-basic.packages.shopware.com <username> <token>
docker compose exec web composer require <package>
```

**First Administration login**: sign in/create a Shopware account (needed for Store extensions), connect the Store, install extensions, configure payment methods. Shop name/language/currency: **Settings > Shop > Basic information**.

## Essential identifiers

- `shopware-cli project console`, `shopware-cli project dev`, `shopware-cli project admin-watch`, `shopware-cli project storefront-watch`
- `--only-extensions`, `--skip-extensions`, `--only-custom-static-extensions`
- `compose.override.yaml`, `.env.local`, `DATABASE_URL`, `APP_ENV`, `auth.json`
- `plugin:install --activate`, `database:migrate --all`, `cache:clear`

## Gotchas

- Do not run `composer` on the host against a Docker project unless host PHP meets requirements (`memory_limit` >= 512M plus extensions); the TUI "Setup health" memory check reflects the container, not host PHP.
- Never edit `compose.yaml` directly - it is regenerated.
- Do not commit `auth.json`.
