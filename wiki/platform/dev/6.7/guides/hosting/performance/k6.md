## What it is

A guide to load-testing a Shopware store with K6 using the `shopware/k6-shopware` repository, which ships JavaScript scenario helpers for Storefront browsing, registration, checkout and Admin API actions.

## When to use

Measuring how a shop behaves under concurrent users before go-live or after configuration changes, including mixed browse/buy/import load.

## Key steps / config

Prerequisites: a Shopware store, K6 installed locally, Bun.

1. Clone and install:
   ```bash
   git clone https://github.com/shopware/k6-shopware.git
   cd k6-shopware
   bun install
   ```
2. `cp .env.example .env` and set the store values/credentials.
3. `bun run fetch-fixtures.ts` — fetches salutation IDs, country IDs and sales channel configuration used to find the sales channel domain and create users/orders.
4. Prepare the shop: no captcha on login/register, email sending disabled (Admin > Settings > System > Mailer > Disable email sending), products and categories present. Generate test data if needed:
   ```bash
   APP_ENV=prod php bin/console framework:demodata
   APP_ENV=prod php bin/console framework:demodata --reset-defaults --products=5000
   APP_ENV=prod php bin/console dal:refresh:index
   ```
   `framework:demodata` may run in parallel; run `dal:refresh:index` after all processes finish.
5. Run the example scenario (helpers from `./helpers/storefront.js`: `visitStorefront`, `visitSearchPage`, `visitNavigationPage`, `accountRegister`, `visitProductDetailPage`, `addProductToCart`, `visitCartPage`, `visitConfirmPage`, `placeOrder`):
   - `k6 run example.js` — 1 virtual user, 1 iteration (smoke check)
   - `k6 run --vus 10 --iterations 100 example.js`
6. Multiple scenarios are declared in the script's `options` object; each maps to an exported function:
   ```javascript
   export const options = {
     scenarios: {
       browse_only: { executor: 'constant-vus', vus: 10, duration: '5m', exec: 'browseOnly' },
       fast_buy:    { executor: 'constant-vus', vus: 1,  duration: '5m', exec: 'fastBuy' },
       import:      { executor: 'constant-vus', vus: 1,  duration: '5m', exec: 'importer' },
     },
   };
   export function setup() { return { token: fetchBearerToken() }; }
   export function importer(data) { useCredentials(data.token); productImport(); /* ... */ }
   ```
   Admin API helpers come from `./helpers/api.js` (`fetchBearerToken`, `useCredentials`, `productImport`, `productChangePrice`, `productChangeStocks`).
7. Web dashboard: `K6_WEB_DASHBOARD=true k6 run --vus 10 --duration 5m example.js`, then open the local dashboard on port 5665 at path `/ui/?endpoint=/`.
8. K6 Cloud (Grafana): create an account and API token to run distributed tests from several locations with Grafana dashboards.

## Essential identifiers

- `k6 run`, `--vus`, `--iterations`, `--duration`, `K6_WEB_DASHBOARD`
- `bun install`, `bun run fetch-fixtures.ts`, `.env.example`
- `framework:demodata`, `--reset-defaults`, `--products`, `dal:refresh:index`
- `options.scenarios`, `executor: 'constant-vus'`, `exec`

## Gotchas

- With scenarios defined, virtual users and iterations can no longer be set on the command line; configure them in `options`.
- Against production, inform the hosting provider first: IPs may be blocked or rate-limited, producing false results. Grafana Cloud is recommended to distribute load.
- The example session ends after `placeOrder` and a new session starts.
