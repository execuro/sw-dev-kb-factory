## What it is

A guide to load-testing a Shopware shop with K6, using the official `shopware/k6-shopware` repository. Scenarios are JavaScript files that simulate many concurrent users browsing, registering and ordering, plus Admin API jobs such as imports.

## When to use

Before go-live or after infrastructure/config changes, to measure how the shop behaves under concurrent load. Prerequisites: a Shopware store, K6 installed locally, and Bun.

## Key steps / config

1. Clone and install:
   ```bash
   git clone https://github.com/shopware/k6-shopware.git
   cd k6-shopware
   bun install
   ```
2. `cp .env.example .env` and set the values (credentials) for your store.
3. Fetch fixtures (salutation IDs, country IDs, sales channel config): `bun run fetch-fixtures.ts`. The tests use them to find the sales channel domain and create users/orders.
4. Prepare the shop: no captcha on login/register forms; email sending disabled (Admin -> Settings -> System -> Mailer -> Disable email sending); products and categories present. Generate test data if needed:
   ```bash
   APP_ENV=prod php bin/console framework:demodata
   APP_ENV=prod php bin/console dal:refresh:index
   APP_ENV=prod php bin/console framework:demodata --reset-defaults --products=5000
   ```
   The default is 1000 products. `framework:demodata` can run several times in parallel; run `dal:refresh:index` once after all processes finish.
5. Run the example scenario (imports helpers such as `visitStorefront`, `visitSearchPage`, `visitNavigationPage`, `accountRegister`, `visitProductDetailPage`, `addProductToCart`, `visitCartPage`, `visitConfirmPage`, `placeOrder` from `./helpers/storefront.js`):
   - `k6 run example.js` — 1 virtual user, 1 iteration (smoke check).
   - `k6 run --vus 10 --iterations 100 example.js` — 10 VUs, 100 iterations.
6. Multiple scenarios: define them in `export const options`, each mapping to an exported function via `exec`:
   ```javascript
   export const options = {
     scenarios: {
       browse_only: { executor: 'constant-vus', vus: 10, duration: '5m', exec: 'browseOnly' },
       fast_buy:    { executor: 'constant-vus', vus: 1,  duration: '5m', exec: 'fastBuy' },
       import:      { executor: 'constant-vus', vus: 1,  duration: '5m', exec: 'importer' },
     },
   };
   ```
   Admin API helpers (`productImport`, `productChangePrice`, `productChangeStocks`, `useCredentials`) come from `./helpers/api.js`; a `setup()` function obtains the token via `fetchBearerToken()` and passes it to `importer(data)`.
7. Live dashboard: `K6_WEB_DASHBOARD=true k6 run --vus 10 --duration 5m example.js`, then open the local dashboard on port 5665 at path `/ui/?endpoint=/`.
8. K6 Cloud (Grafana): create an account and API token to run with more users, chosen user locations and Grafana dashboards.

## Essential identifiers

- `framework:demodata` (`--reset-defaults`, `--products=<n>`), `dal:refresh:index`
- `bun run fetch-fixtures.ts`, `.env.example` / `.env`
- `k6 run`, `--vus`, `--iterations`, `--duration`, `K6_WEB_DASHBOARD=true`
- `options.scenarios`, `executor: 'constant-vus'`, `exec`

## Gotchas

- With `scenarios` defined, VUs and iterations can no longer be set on the command line — configure them in `options`.
- Against production, inform your hosting provider first: your IP may be blocked or rate-limited, producing false results. Grafana Cloud is recommended to spread load across locations.
- `framework:demodata` only runs with `APP_ENV=prod`; otherwise it exits with an invalid-status message.
