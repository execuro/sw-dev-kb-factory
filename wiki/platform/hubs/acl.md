ACL (Access Control List) in Shopware controls who may see and use what in the Administration and, separately, how the B2B Suite and B2B Commercial components model entity- and role-based permissions. Come here instead of grepping directly when deciding how a plugin/app should register a privilege, gate a route/menu/shortcut, or when comparing the core Administration ACL model to the B2B Suite's own ACL/permission systems and their security implications. ACL only governs the Administration UI, never the API by itself — several members below repeat that gotcha explicitly.

- [Administration (6.6)](platform/dev/6.6/concepts/framework/architecture/administration-concept.md) / [Administration (6.7)](platform/dev/6.7/concepts/framework/architecture/administration-concept.md) — near-duplicate concept pages describing the Administration SPA (modules/pages/views/components, `Component.extend`/`override`) and its per-module `acl` directory with roles `viewer`/`editor`/`creator`/`deleter`.
